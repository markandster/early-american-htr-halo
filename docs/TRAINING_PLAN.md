# Halo Competition Training Plan (`early-american-htr-halo`)

This document is the execution-ready, public training and engineering plan for **writer-general 18th-century diplomatic handwriting recognition** (c. 1750–1800 English round hand) using [White Circle Halo](https://github.com/whitecircle/halo).

> **Model & Stage Sequence:** Execute **Gemma 4 (`12B` then `26B-A4B`) first**, followed by **Inkling 2 (`thinkingmachines/Inkling-2-Small` on Halo multi-GPU as Track 2 Primary, with `Inkling-2-Mini` gated on upstream `inkling2_loop` / BF16 support)**, and optionally `Qwen3.6-35B-A3B` if credits remain. Stage 1 runs full-resolution trainable-vision SFT (`scripts/training/sft.py`); Stage 2 runs verifiable-reward **VLM preference optimization (`scripts/training/preference/smpo.py` primary, `dpo.py` secondary)** using deterministic preference pairs scored by `eahtr.rewards`, because Halo's GRPO trainers are verified text-only and reject image columns.

### Non-Goals & Deferred Work
- **Word-level bounding-box JSON emission (Non-Goal):** Autoregressive per-word coordinate JSON increases sequence length ~3–5× per page, exacerbating token-cap non-termination and repetition loops; localization belongs downstream via line segmentation + forced alignment.
- **Writer identification / authorship attribution (Non-Goal):** HTR optimizes writer-invariant transcription; writer attribution is a separate task outside this repo.
- **Halo Multimodal GRPO (`grpo/online`, `grpo/offline`, `grpo/environmental`) on images (Deferred until Halo adds VLM GRPO support):** Verified in Halo's `trainer-architecture.md` and `grpo/offline.md` that Halo GRPO refuses image columns and rejects unknown custom `rewards[].source` plugins. Existing GRPO configs remain scoped strictly to text-only post-correction / contingency recipes unless Dec 1 Track Rules or upstream Halo releases add VLM GRPO.
- **`thinkingmachines/Inkling-2-Mini` (`model_type: inkling2_loop`, NVFP4 `modelopt`) (Blocked pending upstream support):** Live inspection of Hugging Face `config.json` shows `Inkling2LoopForConditionalGeneration` (`inkling2_loop`, `quant_method: modelopt`, `quant_algo: NVFP4`), which neither stock `transformers`/`bitsandbytes` in Colab nor current `whitecircle/halo` (which supports `inkling2_text` / `Inkling-2-Small` and `inkling_text` / `Inkling-Small`) supports yet. Deferred behind **`Inkling-2-Small`** until Dec 1 Track Rules / Halo support `inkling2_loop`.
- **Secondary Bentham R0 `44519` download (Deferred unless ICFHR-2016 diversity saturates):** Verified `CC-BY-4.0` open access (`3.4 GB` compressed), held in reserve behind ICFHR-2016 (`1164045`, `~552 MB`).
- **`Qwen/Qwen3.6-35B-A3B` (Deferred / drop first under credit pressure):** Secondary track only.

### Model-Specific Engineering Rules (Verified Against Hugging Face `config.json` & `whitecircle/halo`)
1. **Gemma 4 (`google/gemma-4-12B-it`, `google/gemma-4-26B-A4B-it`, `gemma4.md`, `peft.md`, `chat_template.jinja`):**
   - `gemma4_unified` (`Gemma4UnifiedForConditionalGeneration`) is natively mapped in `transformers 5.23` (`AutoModelForImageTextToText`, no `trust_remote_code` needed) and verified compatible across Halo's `modality.py` (`config_declares_multimodality`), `family_specs.py` (no `refuses_trl_image_rows`), `buffer_repair.py` (`_fix_per_layer_type_rope`), and `selection.py` (`has_head_dim_beyond_flash`).
   - Both `12B-it` (`Gemma4UnifiedProcessor`) and `26B-A4B-it` (`Gemma4Processor`) default `image_processor.max_soft_tokens`, `image_processor.image_seq_length` (`26B-A4B-it`), and `processor.image_seq_length` to **`280`** (and neither has a `max_pixels` attribute). Loaders **must set all three (`proc.image_processor.max_soft_tokens = 1120`, `proc.image_processor.image_seq_length = 1120`, `proc.image_seq_length = 1120`) when present** and log/assert realized `image_token_id` (`258880`) count (`> 280` and `<= 1120`) on batch 0. Because Halo's `apply_vision_options` (`halo/entrypoints/data_setup.py`) only applies `min_pixels`/`max_pixels` (neither exists on Gemma 4 processors) and never raises `max_soft_tokens`/`image_seq_length` from `280` to `1120`, Halo runs on Gemma 4 must point `model_name_or_path` at a zero-copy symlink directory over the HF cache with patched `preprocessor_config.json` and `processor_config.json` (setting ALL THREE fields when present: nested `image_processor.max_soft_tokens: 1120`, nested `image_processor.image_seq_length: 1120` on `26B-A4B-it`, AND top-level `image_seq_length: 1120`, since `mlx-vlm`'s `Gemma4UnifiedProcessor.from_pretrained()` reads `processor_config.json` first and breaks before reading `preprocessor_config.json`), verified via `log_decoded_samples: true` (`<output_dir>/log/train_sample.txt`) asserting `> 280` and `<= 1120` image tokens per page.
   - **Verified `chat_template.jinja` train/eval prefix parity:** `google/gemma-4-12B-it` and `google/gemma-4-26B-A4B-it` ship byte-identical `chat_template.jinja` files (both using `<|image|>`), so one shared `configs/halo/templates/gemma4_htr_nothink.jinja` serves both checkpoints. With `enable_thinking=False`, `add_generation_prompt=True` emits `<|turn>model\n<|channel>thought\n<channel|>` (+4 empty-thought control tokens), whereas `add_generation_prompt=False` omits `<|channel>thought\n<channel|>`. Therefore:
     - Halo Gemma 4 YAMLs must pin `chat_template: configs/halo/templates/gemma4_htr_nothink.jinja`, `force_chat_template: true`, and `assistant_message_template: "<|turn>model\n<|channel>thought\n<channel|>"` so training and inference share identical prefixes (`compute_completion_spans` matches the exact marker and trains through `<turn|>`).
     - Colab `build_training_batch` constructs `full_str = prompt_str + target_text + eot_token` directly — resolving `eot_token = getattr(tokenizer, "eot_token", None) or ("<turn|>" if "<turn|>" in tokenizer.get_vocab() else tokenizer.eos_token)` so Gemma 4 closes turns with `<turn|>` (id `106`, matching `config.json` `eos_token_id: [1, 106]` and Halo SFT) rather than `<eos>` — never independently calling `apply_chat_template(add_generation_prompt=False)` vs. `True`, and asserts exact token-prefix equality `torch.equal(full_ids[:, :prompt_len], prompt_ids)` plus `> 0` unmasked completion tokens including `<turn|>`; `run_eval_panel` passes `enable_thinking=False` (with `TypeError` fallback) and inspects **generated completion tokens only** (`ids[prompt_len:]` decoded with `skip_special_tokens=False`, excluding the prompt prefix) to count any leaked `<|channel>thought` / `<|content_thinking|>` / `<think>` blocks.
   - FlashAttention-2/3/4 reject Gemma 4's `global_head_dim=512`; both Halo YAMLs and Colab `load_vlm_model` **must set `attn_implementation="sdpa"`**. Verified in `halo/models/attention/selection.py` (`has_head_dim_beyond_flash`) and `halo/model_loading/model_preparation.py` (`apply_family_patches`) that Halo detects `global_head_dim=512` generically across both `gemma4_unified` (`12B-it`) and `gemma4` (`26B-A4B-it`) and applies `patch_sdpa_for_wide_heads()`. On CUDA, Halo upgrades `sdpa` to `sdpa_flex_sliding` (`torch.compile(flex_attention)`) by default: set `HALO_FLEX_SLIDING=0` during short 5-step 24 GB L4 smoke tests (avoiding ~60–120 s Inductor compile overhead and peak compile VRAM) while keeping `HALO_FLEX_SLIDING=1` (default) on competition H100/B200/B300 runs.
   - Gemma 4 `12B` wraps vision projections inside `Gemma4ClippableLinear` (`use_clipped_linears`), causing stock PEFT target lists (`["q_proj", ..., "down_proj"]`) to crash (`Target module ... is not supported`), whereas `all-linear` resolves inner `nn.Linear` submodules safely on dense checkpoints. Note `26B-A4B-it` sets `use_clipped_linears: false`, and using `all-linear` with explicit `exclude_modules=vision_modules` on dense `12B` (when `modules_to_save=vision_modules` trains full vision embedder/projector blocks) prevents double-wrapping.
   - In 4-bit QLoRA (`BitsAndBytesConfig`), set `llm_int8_skip_modules=list(spec.vision_trainable_patterns)` so `modules_to_save` vision modules remain full BF16 (preventing `RuntimeError: only Tensors of floating point and complex dtype can require gradients` on `Params4bit`).
   - Never truncate VLM sequences mid-sample or slice `input_ids` without keeping `mm_token_type_ids` / `token_type_ids` aligned (`MAX_SEQ_LEN = 4096`).
   - For `26B-A4B-it` under `EP=8`: set `moe_balancing: none`, `fp32_experts: true`, **omit** `fp32_non_ep_params`, and **never** use `lora_target_modules: all-linear` under EP (leaves all 128 fused `EPGemma4MoELayer` experts frozen); use `lora_target_modules: [q_proj, k_proj, v_proj, o_proj, gate_up_proj, down_proj]` (`lora_r: 16`, multiple of 8) or full fine-tune (`use_peft: false`, `lr: 5.0e-6` on SFT). When merging native expert LoRA adapters via `merge_peft_adapters.py`, Halo automatically selects shard-by-shard `merge_adapter_streaming`: invoke **without** `--device_map` or `--fp32_norms` (which streaming merge refuses), preserve or recreate any temporary staged base directory recorded in `adapter_config.json` before merging, and verify `processor_config.json` (`1120`) + `chat_template.jinja` in the merged output.
2. **Inkling 2 (`inkling2.md`, `models/README.md`, `family_specs.py`, `chat_template.jinja`):**

   - **`Inkling-2-Small` (`2A` Primary):** 48 layers × 384 routed experts (NVFP4 layers 0–39, MXFP8 layers 40–47, native 23-layer ViT `vision_config`), `quant_method: modelopt`. ### Target Hygiene Rules (`eahtr.hygiene`)
1. Strip `[...]` editorial bracket spans uniformly (`strip_brackets=True`) so XML editorial marks never leak onto clean scans.
2. Normalize `ſ → s` and strip `^` caret markers while preserving case, punctuation, period orthography, and physical line breaks (`\n`).
3. Drop malformed standalone `-` lines and adjacent copy-slip duplicate lines (`has_adjacent_duplicate_lines`), preventing absorbing `-\n` decoder loops.

## 4. Two-Stage Halo Post-Training Pipeline (SFT → Verifiable VLM Preference Optimization)

### 4.1 Stage 1: Full-Resolution Trainable-Vision SFT (`scripts/training/sft.py`)
- **Halo VLM SFT Contract (startup-enforced):**
  - Use `dataset: [...]`, `bf16: true` (mandatory across every SFT, SMPO, DPO, and GRPO Halo YAML — without it Halo's `resolve_training_dtype()` defaults to `torch.float32`, doubling VRAM, disabling `AdamWBF16`, and forcing QLoRA `bnb_4bit_compute_dtype` to FP32), `conversation_field: messages`, `images_field: images`, `packing: false`, `train_on_completions_only: true`, `force_chat_template: true`, exact template + response markers (`chat_template: configs/halo/templates/gemma4_htr_nothink.jinja` with `assistant_message_template: "<|turn>model\n<|channel>thought\n<channel|>"` for Gemma 4; `chat_template: configs/halo/templates/inkling2_htr_nothink.jinja` with `assistant_message_template: "<|message_model|><|content_text|>"` for Inkling 2), and `warmup_steps: 0.05` (fractional warmup).
  - **Never** set `assistant_only_loss`, `completion_only_loss`, `padding_free: true`, `warmup_ratio`, or `max_pixels` in non-Qwen Halo YAMLs (all rejected at startup by Halo).
  - **Never set `test_size`** on pre-split writer-disjoint datasets (`null`/unset preserves existing `train`/`test` splits; a non-null `test_size` causes `halo/data/sources/loading.py` to concatenate `train` and `test` and randomly re-split by row, leaking writers and documents).
  - Pre-filter every VLM split **after accounting for `1120` expanded image tokens** (`1120 + text_tokens <= max_length`, `1120 + prompt_text_tokens <= max_prompt_length`, AND for SMPO `chosen_tokens <= max_length - max_prompt_length` because Halo's `_close_completions()` slices `ids[:max_completion_length]` after appending EOS, silently stripping EOS from over-length `chosen` completions) because Halo's `_filter_vlm_over_length` checks text tokens only while `VLMDataCollator` and `DataCollatorForVLMSMPO` raise `ValueError` mid-epoch on any single over-length expanded row.
  - Because Halo resolves relative `chat_template` paths against **CWD** (`os.path.isfile`), launch Halo training from the repo root (`python /path/to/halo/scripts/training/sft.py configs/halo/...yaml`) or pass an explicit `--chat_template=/abs/path/...jinja`.
  - Pass any Halo CLI overrides after a `.yaml` config strictly in `--key=value` syntax (`HaloArgumentParser._merge_cli_overrides` raises on space-separated `--key value`).
  - Export local Halo VLM datasets as `DatasetDict({"train": ..., "test": ...}).save_to_disk(...)` with Hugging Face `Sequence(Image())` features so Halo's `load_from_disk` reads decoded PIL images cleanly.

  2. **Secondary Ablation — Halo VLM DPO (`scripts/training/preference/dpo.py`, `loss_type: [sigmoid, sft]`):**
