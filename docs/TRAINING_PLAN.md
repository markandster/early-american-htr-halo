# Halo Competition Training Plan (`early-american-htr-halo`)

This document is the execution-ready, public training and engineering plan for **writer-general 18th-century diplomatic handwriting recognition** (c. 1750–1800 English round hand) using [White Circle Halo](https://github.com/whitecircle/halo).

> **Model & Stage Sequence:** Commit **Gemma 4 `12B` (`google/gemma-4-12B-it`)** as the primary submit-ready entry (Stage 1 full-res trainable-vision SFT → optional Stage 2 VLM SMPO with `chosen_sft_ratio: 1.0`, promoted only if it beats continued gold SFT on validation deployment failures). Treat **Inkling 2 (`thinkingmachines/Inkling-2-Small`, image-conditioned with frozen vision)** strictly as **conditional** on passing a bounded Dec 1 cluster train → `export-engine-adapter` → `halo:vllm-0.1.dev25249` serving pilot (Stage 1 SFT alone unless trainable expert-shard reload is proven).

### Model-Specific Engineering Rules (Verified Against Hugging Face `config.json` & `whitecircle/halo`)
1. **Gemma 4 (`google/gemma-4-12B-it`, `gemma4.md`, `peft.md`, `chat_template.jinja`):**
   - `gemma4_unified` (`Gemma4UnifiedForConditionalGeneration`) is natively mapped in `transformers 5.23` (`AutoModelForImageTextToText`, no `trust_remote_code` needed) and verified compatible across Halo's model-loading dispatch. However, **Halo ships text-only Gemma 4 examples and zero `gemma4_unified` (`12B-it`) VLM examples** — so the pre-Dec-1 1× GPU smoke is the first live empirical proof of `gemma4_12b` multimodal training in Halo (verifying collated `VLMDataCollator` batch-0 image tokens + supervised `<turn|>` terminators, nonzero vision gradient + parameter update, and a post-SFT generate-and-stop assertion).
   - `google/gemma-4-12B-it` (`Gemma4UnifiedProcessor`) defaults `image_processor.max_soft_tokens` and `processor.image_seq_length` to **`280`** (and has no `max_pixels` attribute). Because Halo's `apply_vision_options` (`halo/entrypoints/data_setup.py`) only sets `min_pixels`/`max_pixels`, anyone running `gemma4_12b_sft.yaml` directly against the raw HF repo ID would silently train at `280` tokens (`§ 5.1(d)` reproducibility risk). Therefore competition runs must launch via a canonical wrapper script (`scripts/run_gemma4_halo.sh`) that stages the zero-copy `1120`-token processor dir (`scripts/stage_gemma4_highres.py`), passes `--model_name_or_path=<staged_dir>`, and verifies `281 <= image_tokens <= 1120` directly via `verify_processor_image_tokens()` + `VLMDataCollator` batch-0 inspection.
   - **Verified `chat_template.jinja` train/eval prefix parity:** `google/gemma-4-12B-it` ships `chat_template.jinja` using `<|image|>`, pinned via `configs/halo/templates/gemma4_htr_nothink.jinja`. With `enable_thinking=False`, `add_generation_prompt=True` emits `<|turn>model\n<|channel>thought\n<channel|>` (+4 empty-thought control tokens), whereas `add_generation_prompt=False` omits `<|channel>thought\n<channel|>`. Therefore:
     - Halo Gemma 4 YAMLs must pin `chat_template: configs/halo/templates/gemma4_htr_nothink.jinja`, `force_chat_template: true`, and `assistant_message_template: "<|turn>model\n<|channel>thought\n<channel|>"` so training and inference share identical prefixes (`compute_completion_spans` matches the exact marker and trains through `<turn|>`).
     - Colab `build_training_batch` constructs `full_str = prompt_str + target_text + eot_token` directly — resolving `eot_token = getattr(tokenizer, "eot_token", None) or ("<turn|>" if "<turn|>" in tokenizer.get_vocab() else tokenizer.eos_token)` so Gemma 4 closes turns with `<turn|>` (id `106`, matching `config.json` `eos_token_id: [1, 106]` and Halo SFT) rather than `<eos>` — never independently calling `apply_chat_template(add_generation_prompt=False)` vs. `True`, and asserts exact token-prefix equality `torch.equal(full_ids[:, :prompt_len], prompt_ids)` plus `> 0` unmasked completion tokens including `<turn|>`; `run_eval_panel` passes `enable_thinking=False` (with `TypeError` fallback) and inspects **generated completion tokens only** (`ids[prompt_len:]` decoded with `skip_special_tokens=False`, excluding the prompt prefix) to count any leaked `<|channel>thought` / `<|content_thinking|>` / `<think>` blocks.
   - FlashAttention-2/3/4 reject Gemma 4's `global_head_dim=512`; both Halo YAMLs and Colab `load_vlm_model` **must set `attn_implementation="sdpa"`**. Verified in `halo/models/attention/selection.py` (`has_head_dim_beyond_flash`) and `halo/model_loading/model_preparation.py` (`apply_family_patches`) that Halo detects `global_head_dim=512` on `gemma4_unified` (`12B-it`) and applies `patch_sdpa_for_wide_heads()`. On CUDA, Halo upgrades `sdpa` to `sdpa_flex_sliding` (`torch.compile(flex_attention)`) by default: set `HALO_FLEX_SLIDING=0` during short 5-step 24 GB L4 smoke tests (avoiding ~60–120 s Inductor compile overhead and peak compile VRAM) while keeping `HALO_FLEX_SLIDING=1` (default) on competition H100/B200/B300 runs.
   - Gemma 4 `12B` wraps vision projections inside `Gemma4ClippableLinear` (`use_clipped_linears`), causing stock PEFT target lists (`["q_proj", ..., "down_proj"]`) to crash (`Target module ... is not supported`), whereas `all-linear` resolves inner `nn.Linear` submodules safely on dense checkpoints. Using `all-linear` with explicit `exclude_modules=vision_modules` on dense `12B` (when `modules_to_save=vision_modules` trains full vision embedder/projector blocks) prevents double-wrapping.
   - In 4-bit QLoRA (`BitsAndBytesConfig`), set `llm_int8_skip_modules=list(spec.vision_trainable_patterns)` so `modules_to_save` vision modules remain full BF16 (preventing `RuntimeError: only Tensors of floating point and complex dtype can require gradients` on `Params4bit`).
   - Never truncate VLM sequences mid-sample or slice `input_ids` without keeping `mm_token_type_ids` / `token_type_ids` aligned (`MAX_SEQ_LEN = 4096`).
   - Because Halo runs on `gemma4_12b_sft.yaml` use `lora_target_modules: all-linear` (no `modules_to_save` list) whereas Colab uses `modules_to_save=vision_modules` + `exclude_modules=vision_modules`, the Colab vision gradient check does **not** prove Halo's PEFT recipe updates the vision tower; Halo's own 1× smoke must directly verify nonzero vision gradient **and** parameter update on the intended vision module under Halo's recipe.
   - Multi-GPU Halo training runs via `public.ecr.aws/whitecircle/halo:hopper-1.3.0rc2` or `:blackwell-1.3.0rc2` on AWS, Modal, RunPod, or SkyPilot (`sandbox_backend: modal` in Halo is specifically for RL environment sandboxes).
2. **Inkling 2 (`inkling2.md`, `models/README.md`, `family_specs.py`, `chat_template.jinja`):**
   - Tokenizer ships **no `pad_token`** (`tokenizer_config.json`); configs **must set `pad_token: "<|endoftext|>"`** and `moe_balancing: none`.
   - **Verified `chat_template.jinja` silent reasoning default:** Inkling 2's hub template defaults `reasoning_effort` to **`0.9`** (`Thinking effort level: 0.9`, burning reasoning tokens on every page) and intentionally has **no `add_generation_prompt` block** (the model emits `<|message_model|><|content_text|>` itself after `<|message_user|>...<|end_message|>`, matching Halo SFT's `PADDED_SPAN_POLICY: include_marker=True` and Halo SMPO's `render_prompt_completions`), while Halo VLM SMPO refuses `reasoning_effort_field`. Fix cleanly across SFT and SMPO by pinning `chat_template: configs/halo/templates/inkling2_htr_nothink.jinja` (changing only default effort `0.9` → `0.0` so it emits `Thinking effort level: 0`, without inventing an `add_generation_prompt` suffix) with `force_chat_template: true` and `assistant_message_template: "<|message_model|><|content_text|>"` (terminating on `<|end_message|><|content_model_end_sampling|>`, `eos_token_id: 200006`); eval inspects generated completion tokens for leaked `<|content_thinking|>` tags.
   - **`Inkling-2-Small` (`2` Conditional Track):** 48 layers × 384 routed experts (NVFP4 layers 0–39, MXFP8 layers 40–47, native 23-layer ViT `vision_config`), `quant_method: modelopt`, and **zero shipped VLM SFT examples in Halo**. Requires **`frozen_quantized_experts: true`**, `expert_parallel_size >= 2`, `expert_tensor_parallel_size: 1`, `ep_lazy_loading: true`, `merge_expert_lora_on_save: false`, **`lora_r % 8 == 0`** (`GROUPED_MM_STRIDE_ALIGNMENT_BYTES`), and **`lora_target_modules: [o_proj, gate_up_proj, down_proj]`** (`o_proj` + routed experts stay off the vision tower, so describe this arm strictly as **image-conditioned training with frozen vision** unless measured weights prove otherwise). Also **measure real Inkling image-token counts per row** with Inkling's actual processor rather than assuming Gemma 4's `1120` budget (`export_halo_datasets.py`), and measure real full-length (`4096`) GPU memory on Dec 1 (Halo documents `181.8 GiB/rank` at `EP=2` before step 1, and per-token KV/recompute figures suggest a `4096`-token SMPO pair could reach `~90 GiB/rank` at `EP=8`, exceeding 80 GB H100s; therefore keep `inkling2_small_*` gated on a Dec 1 full-length GPU smoke). Saved adapters over frozen quantized experts **cannot merge** (`merge_peft_adapters.py` refuses them) and Halo `53fe34a` provides no Stage 2 `adapter_path` reload flag — so unless an experimental restart proves expert-shard adapter reload works, **Stage 1 SFT alone** is the defensible Inkling entry. Before funding a full Inkling run, run a **bounded Dec 1 smoke + train → `export-engine-adapter` → `halo:vllm-0.1.dev25249-1.3.0rc2` serving pilot** sending real manuscript images, performing an image-swap test, verifying rendered `Thinking effort level: 0` at the server, and comparing base-vs-adapter and trainer-vs-server log-probs.

### Target Hygiene Rules, Diplomatic Conventions & Hard-Case Panel (`eahtr.hygiene`)
1. **Prompt & Convention Alignment (`39%` of RevCity has `[...]` deletions or `[___]` damage):** Preserve **both raw and cleaned references** (`raw_text`, `text`). Because `strip_brackets=True` turns struck-out text into clean final text and naive regex leaves artifacts like `m[_]ung` → `m ung`, make the training/inference prompt explicitly instruct final clean reading (omitting crossed-out `[...]` spans and normalizing intra-word damage tokens cleanly), spot-check a stratified sample against scans, and **report zero-shot baseline under BOTH raw-with-deletions and cleaned final-text targets** so visual gains are separated from convention learning.
2. Clean target (`text`): normalize `ſ → s`, strip `^` carets cleanly, preserve case, punctuation, period orthography, physical line breaks (`\n`), and preserve annotated ALTO reading order by default (`sort_regions=False`, with opt-in `sort_regions=True` geometric ablation).
3. **Hard-case panel (separately scored, never silently dropped from evaluation):** Keep genuine blanks, endorsements, lists, dense pages, two-page openings, and repeated marks/leader dots in `hard_case_panel.jsonl` (tagged with `is_blank_page`, `ground_truth_status`, and `panel_role`) alongside strictly disjoint `hard_case_held_out.jsonl`, reporting blank-page hallucinations alongside omissions on sparse pages; retain training-side drop filters transparently in corpus stats. *(Note: none of 9,958 sampled RevCity reference lines is a standalone dash, so loop suppression targets model-generated failure modes.)*

## 4. Two-Stage Halo Post-Training Pipeline (SFT → Verifiable VLM Preference Optimization)

### 4.1 Stage 1: Full-Resolution Trainable-Vision SFT (`scripts/training/sft.py`)
- **Halo VLM SFT Contract (startup-enforced):**
  - Use `dataset: [...]`, `bf16: true` (mandatory across every SFT, SMPO, and GRPO Halo YAML — without it Halo's `resolve_training_dtype()` defaults to `torch.float32`, doubling VRAM, disabling `AdamWBF16`, and forcing QLoRA `bnb_4bit_compute_dtype` to FP32), `conversation_field: messages`, `images_field: images`, `packing: false`, `train_on_completions_only: true`, `force_chat_template: true`, exact template + response markers (`chat_template: configs/halo/templates/gemma4_htr_nothink.jinja` with `assistant_message_template: "<|turn>model\n<|channel>thought\n<channel|>"` for Gemma 4; `chat_template: configs/halo/templates/inkling2_htr_nothink.jinja` with `assistant_message_template: "<|message_model|><|content_text|>"` for Inkling 2), and `warmup_steps: 0.05` (fractional warmup).
  - **Never** set `assistant_only_loss`, `completion_only_loss`, `padding_free: true`, `warmup_ratio`, or `max_pixels` in Gemma 4 / Inkling 2 Halo YAMLs (all rejected at startup by Halo).
  - **Never set `test_size`** on pre-split writer-disjoint datasets (`null`/unset preserves existing `train`/`test` splits; a non-null `test_size` causes `halo/data/sources/loading.py` to concatenate `train` and `test` and randomly re-split by row, leaking writers and documents).
  - **Strict `test_public` isolation:** Map Halo's internal `test` split strictly to **`validation`** (`DatasetDict({"train": ..., "test": val_ds})`), never `test_public`. Evaluate `test_public` once through a standalone frozen-eval CLI after locking checkpoint, decoding settings, and metrics; key development cache artifacts by `(manifest_hash, model_rev, processor_hash, template_hash, git_commit, config_hash, seed)`.
  - Pre-filter every VLM split **after accounting for `1120` expanded image tokens** (`1120 + text_tokens <= max_length`, `1120 + prompt_text_tokens <= max_prompt_length`, AND for SMPO `chosen_tokens <= max_length - max_prompt_length` because Halo's `_close_completions()` slices `ids[:max_completion_length]` after appending EOS, silently stripping EOS from over-length `chosen` completions) because Halo's `_filter_vlm_over_length` checks text tokens only while `VLMDataCollator` and `DataCollatorForVLMSMPO` raise `ValueError` mid-epoch on any single over-length expanded row.
  - Because Halo resolves relative `chat_template` paths against **CWD** (`os.path.isfile`), launch Halo training from the repo root (`python /path/to/halo/scripts/training/sft.py configs/halo/...yaml`) or pass an explicit `--chat_template=/abs/path/...jinja`.
  - Pass any Halo CLI overrides after a `.yaml` config strictly in `--key=value` syntax (`HaloArgumentParser._merge_cli_overrides` raises on space-separated `--key value`).
  - Export local Halo VLM datasets as `DatasetDict({"train": ..., "test": val_ds}).save_to_disk(...)` with Hugging Face `Sequence(Image())` features so Halo's `load_from_disk` reads decoded PIL images cleanly.
- **Validation & Vision-Dependence Controls (Dev = Train / Val Only):**
  - `should_use_4bit(spec, VRAM_GB, arm)` prevents zero-shot OOM on 24 GB L4 / 40 GB A100 while preserving full BF16 when VRAM suffices, and fails closed cleanly if pointed at an unsupported `modelopt` checkpoint.
  - **Halo-native matched sham control + same-checkpoint image-swap test:** Run the matched sham control **inside Halo at equal optimizer steps and token budget** (deranging identical pilot pages within length bands across documents; stop claiming Colab `sham_short` matches Halo), AND evaluate the same trained checkpoint on correct vs. swapped images as a direct pixel-dependence check.
  - **Halo-native vision gradient & parameter-update check:** Verify nonzero vision gradients and actual parameter updates inside Halo's own PEFT/FSDP config (not only Colab's `modules_to_save` recipe), alongside step-1 `grad.norm()` checks on Colab BF16 skip modules.

### 4.2 Stage 2: Verifiable-Reward VLM SMPO (Dec 3 Gate vs. Continued Gold SFT & Repetition Penalty)
- **Why VLM SMPO instead of Halo GRPO on Images:** Verified in `whitecircle/halo` docs (`trainer-architecture.md`, `grpo/offline.md`, `grpo/rewards/README.md`) that:
  1. `OfflineGRPOTrainer` and `DistributedOnlineGRPOTrainer` have **no vision data path** and explicitly refuse image columns.
  2. `rewards:` YAML terms accept only Halo's built-in `source` types (`accuracy`, `format`, `judge`, `reward_model`, `whitecircle`, `environment`).
- **Stage 1 → Stage 2 Checkpoint Continuity Gate (Mandatory):**
  - Build a unified **merge → rollout → eval** runner (`scripts/merge_and_eval_halo.py`, `scripts/generate_halo_rollouts.py`) so Halo SFT checkpoints hand off reproducibly.
  - Save Stage 1 SFT, merge + verify (`Gemma 4`), and restart in a **fresh process**. On two fixed image/prefix pairs, compare teacher-forced log-probabilities across `base` → `end-of-SFT` → `Stage-2 step-0`, requiring a measurable SFT delta and Stage-2 step-0 continuity within precision tolerance (`reject_adapter_directory` refuses unmerged PEFT dirs). For `Inkling-2-Small`, unless expert-shard adapter reload is proven on frozen banks, stop Inkling at Stage 1 SFT.
- **Deterministic Verifiable Scoring Engine & Pair-Builder Rules (`eahtr.rewards`):**
  Generate $K = 4$ rollouts from the **actual frozen Halo Stage 1 SFT policy** on **out-of-fold / held-out non-test pages Stage 1 did not memorize** (stratified across writers & lengths, including deployment greedy decoding alongside stochastic samples; tie `max_new_tokens` cap to reference length `>= 2048` / `ceil(1.5 * ref_tokens)` covering RevCity's `4,705`-char long pages; budget wall-clock explicitly from measured pilot `tok/s`, `usable pairs / GPU-hr`, and `p95` decode length), score with:

  3. Blind-audit pair directions near `margin ≈ 0.05`, log unusable/tie/loop/close-paleography breakdown, and run **independent `audit_split_disjointness` across preference train/val splits**.
  4. **Halo VLM SMPO Objective, Repetition-Penalty Baseline & Dec 3 Go/No-Go Gate (`halo/trainers/preference/smpo.py#L284-L286`):** Halo computes `margin_loss + chosen_sft_ratio * chosen_sft_loss + (1 - chosen_sft_ratio) * rejected_sft_loss`; therefore set **`chosen_sft_ratio: 1.0`** (never `0.75`, which adds `+0.25` NLL supervision onto rejected loops) unless validation decoding proves otherwise.
